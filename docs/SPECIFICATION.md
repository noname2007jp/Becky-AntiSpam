# Becky AntiSpam 製品仕様書

- 文書版数: 1.0（開発中仕様）
- 更新日: 2026-11-06
- 対象製品: Becky! Internet Mail Ver.2.83.11（32bit / x86）
- 対象OS: Windows 64bit
- プラグイン形式: Win32 / x86 DLL
- 状態: 開発中。Becky!実機でのロード・受信動作は未確認

## 1. 目的

Becky! Internet Mailで受信するメールをローカル環境で解析し、迷惑メールの可能性を判定する。ルール判定とベイジアン学習を組み合わせ、判定結果・スコア・判定理由を記録する。

初期段階では誤判定によるメール消失を防ぐため、判定結果を記録する監査モードを標準とする。メールの自動移動は将来機能とし、利用者が明示的に有効化した場合に限る。メール削除機能は設けない。

## 2. 基本方針・設計原則

1. 判定・学習は原則としてPC内で完結させる。
2. メール本文、完全ヘッダー、添付ファイルを学習DBや通常ログへ保存しない。
3. メール内容・学習データを外部へ送信しない。AI API等の外部連携は別機能として、初期状態OFF、送信内容の明示と利用者の操作を必須とする。
4. 初期設定は監査・判定のみとし、メールの移動・削除を行わない。
5. 解析対象のサイズ、MIME階層、パート数、処理量に上限を設ける。
6. DLL境界の外へ例外を伝播させない。
7. ログは用途別にON/OFFでき、詳細テストログは初期状態OFFとする。
8. Becky!本体と同じ32bit/x86でビルドする。

## 3. 処理対象と処理フロー

### 3.1 受信メール

1. Becky!の受信前フィルターコールバックからメールソースを受け取る。
2. サイズ上限を確認する。
3. RFC 5322ヘッダーとMIME構造を解析する。
4. 件名・ヘッダー特徴・本文から判定用テキストを生成する。
5. ルール判定とベイジアン判定を実行する。
6. 正常／要確認／迷惑メールの判定、スコア、判定理由を得る。
7. 監査ログへ結果を記録する。
8. 初期設定ではBecky!標準フィルターへ処理を戻し、メールの移動・削除を行わない。

### 3.2 手動処理（将来機能）

選択メールの判定、正常／迷惑の確定学習、再判定、一括処理を提供する。学習は利用者がラベルを明示した場合に限る。現時点では手動メニュー・操作UIは未実装。

## 4. 判定仕様

### 4.1 判定区分

| 区分 | 意味 |
|---|---|
| 正常 | 現時点の判定スコアが要確認閾値未満 |
| 要確認 | 迷惑メールと断定できないが注意を要する |
| 迷惑メール | 迷惑メール閾値以上 |

スコアは0～100の範囲に制限する。閾値は設定値として管理する設計とし、運用開始前に誤検知・見逃しの検証を行う。

### 4.2 判定方式

- ルールベース: 認証情報を急がせる表現、IPリテラルURL、Punycode等を評価する。
- ベイジアン判定: 正常・迷惑として利用者が確定したメールから学習した単語統計を利用する。
- 学習件数が少ない間はBayesスコアの寄与を抑える。
- 判定結果にはスコア、Bayes確率、適用ルールと理由を付与する。
- 送信者アドレス自体はBayes特徴語に含めない。

### 4.3 認証情報の信頼性

Authentication-Resultsはメール内に偽装される可能性があるため、受信サーバーのauthserv-id等を検証できるまで認証結果を信頼しない。Return-Pathも信頼できる受信経路で付与されたと確認できる場合のみ評価する。未検証情報を認証成功・失敗として断定的に利用しない。

## 5. メール解析仕様

- RFC 5322ヘッダーの解析、折り返し行の展開
- RFC 2047 B/Q encoded-wordの復号
- MIME multipartの再帰解析
- text/plainを優先し、なければtext/htmlから本文候補を抽出
- Base64およびquoted-printableのテキスト部分の復号
- Windows環境でUTF-8、Shift_JIS/Windows-31J、EUC-JP、ISO-2022-JP等を変換
- 添付ファイルはメタデータのみ取得し、実行・展開・保存しない
- SHA-256は受信メールの生バイト列に対して計算し、同一内容の重複学習防止に利用

### 5.1 解析上限（現行実装値）

| 項目 | 上限 |
|---|---:|
| メールソース | 5 MiB |
| ヘッダー領域 | 256 KiB |
| ヘッダー数 | 200 |
| MIMEパート数 | 100 |
| MIME再帰深度 | 8 |
| 抽出テキスト合計 | 2 MiB |
| トークナイザー入力 | 1 MiB |
| 特徴語数 | 20,000 |

上限超過・不正形式の場合は安全側に処理を中断または警告し、Becky!本体を停止させないことを受け入れ条件とする。

## 6. 日本語トークナイズ

初期実装は外部依存のないUTF-8トークナイザーを利用する。

- 日本語文字列から重複を除いた2-gramを抽出
- カタカナ連続語は複合語も特徴語として保持
- ASCII英数字は小文字化
- 数字だけのIDは原則除外
- 送信者メールアドレスはBayes特徴語に含めない
- MeCab等の形態素解析器は、Win32/x86互換性と辞書・ライブラリのライセンス確認後に任意導入を検討する

## 7. 学習・データ保存仕様

### 7.1 保存場所

既定の保存先は次のとおり。

`<Becky!インストール先>\\Plugins\\BeckyAntiSpam\\`

主なファイル:
- `training.sqlite3`: 学習統計・重複学習防止情報
- `operation.log`: 通常ログ
- `test-detail.log`: 詳細テストログ
- `settings.ini`: ログ等の設定

### 7.2 SQLite保存内容

現行スキーマの中心は次の情報。

- トークンごとの正常／迷惑メール文書頻度
- 正常／迷惑の学習件数
- 重複学習防止用SHA-256ハッシュと学習日時
- スキーマ等のメタ情報

メール本文、完全ヘッダー、添付ファイルは保存しない。安心／迷惑アドレスリスト、AI仮判定テーブルは設計対象だが、現行スキーマへの実装有無は別途確認する。

### 7.3 学習ルール

- 学習は利用者が正常／迷惑を明示した場合に行う。
- 同一メールの同一ラベルでの重複学習を防ぐ。
- 同一ハッシュに異なるラベルが指定された場合は、旧ラベルの統計を差し引いて再分類する。
- 学習処理はトランザクションで一貫性を確保する。
- 学習本文は永続化せず、特徴語統計のみを保存する。

### 7.4 容量管理

- 語彙数上限を設け、低頻度語を優先して整理する。
- DB圧縮前にSQLiteバックアップAPIで内部バックアップを作成する。
- 整理後にSQLite整合性確認を行う。
- VACUUMは受信処理中に実行せず、保守処理として実施する。
- 学習履歴を期限削除した場合、古いメールが再学習される可能性があることを明示する。

## 8. ログ・デバッグ仕様

### 8.1 設定

設定ファイル: `<Becky!インストール先>\\Plugins\\BeckyAntiSpam\\settings.ini`

```ini
[logging]
enabled=1

[test_mode]
enabled=0
```

| 設定 | 値 | 動作 |
|---|---|---|
| logging.enabled | 1 | ログ出力全体を有効化 |
| logging.enabled | 0 | 通常・詳細ログをすべて停止 |
| test_mode.enabled | 1 | 詳細テストログを有効化 |
| test_mode.enabled | 0 | 詳細テストログを停止 |

通常ログは初期状態ON、詳細テストログは初期状態OFF。設定はプラグイン初期化時に読み込む。

### 8.2 通常ログ

ファイル: `operation.log`

記録内容:
- プラグイン初期化・終了
- DB／パイプライン初期化結果
- メール判定区分とスコア
- 処理失敗・例外等のエラー

通常ログのローテーション目安は約5 MiB、旧ログ1世代。

### 8.3 詳細テストログ

ファイル: `test-detail.log`

記録内容:
- コールバック処理開始、入力サイズ
- MIMEパート数、ヘッダー数、添付メタデータ数
- 本文切り詰めの有無
- 判定区分、スコア、Bayes確率
- 適用ルール名、ルールスコア、理由
- 学習件数、語彙数
- 解析警告、パイプラインエラー、例外

詳細ログのローテーション目安は約20 MiB、旧ログ1世代。

### 8.4 ログに記録しない情報

- メール本文
- 件名
- 送信者アドレス
- ヘッダーの具体的な値
- 添付ファイル本体
- APIキー、パスワード等の認証情報

ログ出力時は改行によるログ偽装を防止する。詳細ログは障害解析用であり、通常運用ではOFFを推奨する。ログには内部判定情報が含まれるため、共有前に内容を確認する。

### 8.5 ログ受け入れ条件

1. 通常ログONで起動・判定・エラーが記録される。
2. 詳細ログOFFでは詳細ファイルに新規記録しない。
3. 詳細ログONで解析情報・判定根拠・警告が記録される。
4. logging.enabled=0では両ログとも出力されない。
5. ローテーション後もログ出力が継続する。
6. メール本文・件名・送信者・ヘッダー値がログに含まれない。

## 9. Becky!連携仕様

- 対象DLLはWin32/x86。
- 受信前フィルターコールバックを主要な判定入口とする。
- 初期状態ではBecky!標準フィルターを妨げず、メール操作を変更しない。
- メニューによる手動判定・手動学習は今後実装する。
- コールバックのABI、構造体、戻り値、メモリ所有権、実行時間、スレッド条件はSDK定義とBecky! 2.83.11実機で検証する。
- CIでDLLが生成できたことは、Becky!本体でロード・動作することの証明ではない。

## 10. AI API連携（将来機能）

- 初期状態OFF。
- ローカル判定だけで利用可能であること。
- 外部送信する項目・目的・送信先を設定画面で明示する。
- メール本文・ヘッダーの送信は利用者の明示的な許可を必須とする。
- API判定結果は仮ラベルとし、利用者が確認するまで確定学習しない。
- 受信コールバック内でAPI応答を待たない。
- APIキーはDPAPI等で保護し、ログに出力しない。
- タイムアウト・通信失敗時はローカル判定を維持する。

## 11. メール操作・安全要件

| 操作 | 方針 |
|---|---|
| 判定・記録 | 初期状態で有効 |
| 手動判定 | 実装予定 |
| 手動学習 | 実装予定。利用者の明示操作が必要 |
| 自動移動 | 初期状態OFF。監査試験後に実装 |
| メール削除 | 実装しない |
| 外部送信 | 初期状態OFF。明示的な許可が必要 |

## 12. 非機能要件

- Becky!と同じWin32/x86 ABIで動作する。
- 受信処理を不必要に遅延させない。
- 不正・巨大メールでBecky!をクラッシュさせない。
- ログ・DBへの保存量を制限する。
- SQLite更新はトランザクションで行う。
- PC移行はBecky!を終了した状態でデータ保存先フォルダー全体をコピーする方式とする。
- プラグイン設定画面に実際のデータ保存先と「フォルダーを開く」「移行方法」ボタンを表示する。
- 独自のインポート／エクスポート機能およびSQLite復元APIは設けない。
- CIでWin32/x86ビルドと単体テストを実行する。
- 実機試験結果をCI結果と分けて管理する。

## 14. 受け入れ試験

### 14.1 ビルド・ロード
- Win32/x86でDLLがビルドできる。
- Becky! 2.83.11がDLLを認識し、起動・終了できる。
- 必須コールバックが正しいABIで呼び出される。

### 14.2 受信・判定
- 通常メール、迷惑メール、文字化けメール、multipart、HTMLのみ、添付ありを判定できる。
- サイズ上限・MIME深度上限を超えたメールでもBecky!が停止しない。
- 初期監査モードでメールの移動・削除・内容変更が起きない。
- Becky!標準フィルターとの共存を確認する。

### 14.3 学習・DB
- 正常／迷惑学習がDB再起動後も維持される。
- 同一メールの二重学習が防止される。
- ラベル訂正時に統計が一貫して更新される。
- DBバックアップ・整合性確認・圧縮後に再オープンできる。

### 14.4 ログ
- 通常ログと詳細テストログを独立して切り替えられる。
- 全ログ停止設定が優先される。
- ローテーションが動作する。
- ログにメール本文・件名・送信者・ヘッダー値が残らない。

### 14.5 運用評価
- 正常メール・迷惑メールの評価セットで誤検知率と見逃し率を測定する。
- 受信処理時間とDB容量を測定する。
- テストモードのログを用いて不具合を再現・修正できる。
- 自動移動を解放する前に、監査期間と誤判定率の許容基準を決定する。

## 15. 変更管理

本書は開発中の基準仕様である。実装が仕様と異なる場合は、まず差異を記録し、実装・仕様のどちらを変更するか決定する。未実装機能を実装済みとして扱わない。実機未確認項目は必ず未確認と明記する。


### ポータブル保存先・PC移行

保存先はまず Becky! 実行ファイルのあるフォルダーを基準とした `Plugins\\BeckyAntiSpam\\` を使用し、書き込み権限がない場合は `%APPDATA%\\BeckyAntiSpam\\` に切り替える。設定画面には実際の保存先を表示する。設定画面の「移行方法」では、移行元・移行先のBecky!を完全に終了し、移行元フォルダー全体をコピーして移行先の表示された保存先へ上書きする手順を案内する。SQLiteはWALモードのため、Becky!終了後にコピーすることを必須とする。独自のインポート／エクスポート機能やSQLite復元APIは実装しない。
