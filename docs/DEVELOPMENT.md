# 開発メモ

## 確定した実行・ビルド環境

- Becky!: Internet Mail Ver.2.83.11
- Becky!アプリケーション: 32bit / x86
- OS: 64bit Windows
- プラグインDLL: Win32 / x86（Becky!本体と同じビット数）
- CMake generator platform: `-A Win32`

## SDK調査結果

アップロードされた `B2PinSDK-26400.zip` を調査済み。詳細は [SDK-ANALYSIS.md](SDK-ANALYSIS.md) を参照。

確認できた主な事項:

- 自動振り分け前のコールバックは `BKC_OnBeforeFilter2`。
- 受信後コールバックは `BKC_OnRetrieve`。
- 手動判定用にメニュー登録、選択メール列挙、メールソース取得、フォルダ移動APIがある。
- `BKC_OnPlugInInfo` は必須で、プラグイン名とベンダー名を設定する。
- SDKのサンプルプロジェクトはWin32構成のみ。

## Becky!プラグインDLLの実装状況

監査専用のWin32/x86 DLLターゲットを追加済み。エクスポートするコールバックは `BKC_OnPlugInInfo`、`BKC_OnStart`、`BKC_OnExit`、`BKC_OnMenuInit`、`BKC_OnBeforeFilter2`。受信前コールバックは常に標準フィルターへ処理を戻し、移動・削除を実行しない。監査ログは判定区分・スコア・Bayes確率のみを記録する。

GitHub ActionsのWin32/x86構成でDLLビルド・単体テスト・成果物アップロードまで確認済み。Becky! 2.83.11への配置・ロード・受信コールバックの実機確認は未実施。

## 次の実装ステップ

1. SDKヘッダーとサンプルのエクスポート定義をプロジェクトへ取り込む。
2. Visual Studio 2022 / Win32で最小DLL（PlugInInfo / Start / Exit）を作成する。
3. Becky! 2.83.11がDLLを認識・ロードするか確認する。
4. `BKC_OnBeforeFilter2` で受信メールを読み取り、判定だけを行う監査モードを実装する。
5. 手動メニューと選択メール取得を実装する。
6. フォルダ移動は明示設定後に有効化し、標準フィルターとの共存を検証する。

## 実装上の安全策

- 最初は判定結果をログへ出すだけの監査モードとする。
- 自動振り分けはユーザーが明示的に有効化した場合だけ動作させる。
- 削除は実装しない。迷惑メール用フォルダへの移動のみを検討する。
- SPF/DKIM/DMARCは、受信側サーバーが付与した認証結果を信頼境界を考慮して利用する。ヘッダー文字列だけで真正性を断定しない。
- 添付ファイルは開かず、初期段階では解析対象外とする。
- 学習データとログはローカル保存し、メール本文をログに残さない。
- メールソースの長さを固定長と仮定しない。過大入力や不正MIMEでBecky!を停止させない。
- DLL境界を越えてC++例外を伝播させない。

## 現在のエンジンの制限

初期エンジンは判定方式の骨格であり、本番向けスパム判定器ではない。日本語は2-gram方式の簡易トークナイザーであり、形態素解析による単語境界の精度は今後の改善課題。MIME解析・SQLite永続化は初期実装済みだが、不正メールへの網羅的な堅牢性評価、誤判定率の実メール評価、Becky!実機検証は未完了。

## 拡張機能の設計方針（2026-11-06）

統合仕様は [FEATURE-SPEC.md](FEATURE-SPEC.md)、作業順は [ROADMAP.md](ROADMAP.md) を参照。

追加で採用する設計:
- Annoyance Filterを参考にしたベイジアン確率計算・判定保留
- 深海魚フィルターを参考にした日本語解析、安心/迷惑リスト、再判定、学習DB管理
- 秀丸スパムフィルターを参考にした迷惑ワード、URL、添付、発信国の補助判定
- AI APIは初期OFF。受信処理をブロックしない非同期照会とし、AI判定は仮ラベルに留め、ユーザー確認後に教師データへ反映
- 学習DBはメール本文を保存せず、単語統計・最小限の履歴を保持。語彙上限、低頻度語整理、バックアップ、VACUUMを設計に含める

### メール処理パイプライン

`MailPipeline` を追加し、生メール解析、ローカル判定、SHA-256重複防止、SQLiteへの確定学習を接続。分類と学習は同一の `classifier_text` を使用する。学習時にDBへ保存するのはトークン統計とハッシュ履歴で、本文・ヘッダーは保存しない。

### 日本語トークナイザー

外部依存のないUTF-8トークナイザーを実装済み。日本語連続文字列は重複を除いた2-gramに分割し、カタカナ連続語は複合語としても保持する。ASCII英数字は小文字化し、数字のみのIDは除外する。トークナイザーはインターフェース化しており、MeCab等の任意実装へ差し替え可能。MeCab採用時は本体・辞書それぞれのライセンスと再配布条件を確認する。

### 学習データの整理方針

- まず文書頻度を集約し、メール本文を保存しない。
- 語彙数・DB容量に上限を設ける。
- 整理は低頻度・長期間未使用の語彙から行う。
- 自動整理の前にバックアップを作成する。
- AIの未確認判定を確定学習へ直接投入しない。
- スリム化後の誤検知率・見逃し率を回帰テストする。



## ログ・テストモード

設定ファイルは `%APPDATA%\\BeckyAntiSpam\\settings.ini`。未作成時の既定値は通常ログON、詳細テストログOFF。

- `[logging] enabled=1|0`: `operation.log` の出力切り替え。OFFならファイルログをすべて停止。
- `[test_mode] enabled=1|0`: `test-detail.log` の詳細出力切り替え。通常ログとは独立してON/OFF可能。ただし logging.enabled=0 の場合はどちらも停止。
- 通常ログは判定区分・スコア・初期化／処理エラー等を記録し、約5MiBで1世代ローテーション。
- 詳細ログは入力サイズ、MIME構成、Bayes確率、学習件数、語彙数、判定ルールと理由、解析警告、内部エラーを記録し、約20MiBで1世代ローテーション。
- メール本文・件名・送信者・ヘッダー値はログへ出力しない。テストログは機密情報を含む可能性がある運用環境では無効にする。

設定例は [settings.ini.example](../config/settings.ini.example)。
