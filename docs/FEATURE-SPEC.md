# 機能仕様（初版）

## 1. 対象と基本方針

- 対象: Becky! Internet Mail Ver.2.83.11（32bit / x86）
- OS: 64bit Windows
- DLL: Win32 / x86 のみ
- 基本判定: ローカル完結。ネットワーク接続なしでも判定・学習できること
- 初期動作: 監査・判定のみ。自動振り分けは明示的な有効化が必要
- メール削除機能は実装しない
- メール本文・ヘッダーを通常の学習DBやログへ保存しない

## 2. 判定エンジン

### 2.1 ハイブリッド判定
1. ルール判定
2. ベイジアン判定
3. 各判定のスコア統合
4. 正常 / 要確認 / 迷惑メールの3段階判定

判定結果にはスコア、判定理由、エンジンバージョンを保持する。閾値は設定可能とし、初期値は誤検知を抑える保守的な値とする。

### 2.2 ベイジアン判定
- Annoyance Filterの公開アルゴリズム・設計思想を参考に独自実装する。
- 正常・迷惑の学習件数と単語ごとの文書頻度を管理する。
- 学習は同一メールの重複登録を防ぐ。
- 学習データが少ない間はベイジアン判定の寄与を抑える。
- ユーザーが正常/迷惑を確定したメールを教師データとして扱う。
- AIの未確認判定は仮データとして分離し、確定学習に混ぜない。

### 2.3 メール解析・MIME
- RFC 5322形式のヘッダーを解析し、折り返し行を展開する。
- RFC 2047のB/Q encoded-wordを復号する（WindowsではUTF-8、Shift_JIS、EUC-JP、ISO-2022-JP等の一般的な文字コードをUTF-8へ変換。未知の文字コードは元バイト列を保持）。
- `Authentication-Results` と `Return-Path` は未検証状態で判定スコアに利用しない。
- MIME multipartを再帰解析し、text/plainを優先、なければtext/htmlからタグを除去して本文候補を抽出する。Windowsでは主要な日本語文字コードをUTF-8へ変換する。
- Base64 / quoted-printableを本文テキストに限って復号する。添付ファイル本体は実行・展開・保存しない。
- メールサイズ、ヘッダーサイズ・数、MIMEパート数・深さ、抽出本文サイズに上限を設ける。
- SHA-256は受信した生メール全体のバイト列から計算する。正規化は行わず、同一内容の完全一致を重複判定対象とする。

## 2.4 日本語解析
- 初期実装は外部依存のないUTF-8トークナイザーとし、日本語連続文字列から重複を除いた2-gramを抽出する。カタカナ連続語は複合語も特徴語として保持する。
- ASCII英数字は小文字化し、数字のみのIDは語彙汚染を避けるため除外する。送信者メールアドレスはベイジアン特徴語に含めない。
- 解析資源保護のため、トークナイザーへの入力は最大1 MiB、出力特徴語は最大20,000件に制限する。
- トークナイザーをインターフェース化し、MeCab等の形態素解析器を任意実装として差し替え可能にする。採用時はWin32/x86互換性、本体・辞書それぞれのライセンスと再配布条件を確認する。
- 英数字、URL、メールアドレス、長い連続文字列を正規化し、個人情報やランダムIDが語彙を汚染しないようにする。

### 2.5 メール処理パイプライン
- 生メールをパーサーで解析し、件名・ヘッダー特徴・本文から判定入力を生成する。
- 分類時と学習時は同一のテキスト生成関数を利用する。
- 学習時は生メール全体のSHA-256で重複を識別し、SQLiteには特徴語統計とハッシュ履歴のみを保存する。
- パイプラインはメールの移動・削除・外部通信を行わない。

## 3. ルール・リスト機能

- 迷惑ワード辞書: カテゴリ・重み・有効/無効を管理
- 信頼ワード: 一致時にスコアを減算。ただし単独で完全許可しない
- 安心差出人・安心ドメイン: ユーザーが登録したものを優先
- 迷惑差出人・迷惑ドメイン: ユーザーが登録したものを判定に反映
- 送信先からの自動信頼登録: オプション。初期OFF。候補登録を基本とし、From一致だけで完全許可しない
- SPF/DKIM/DMARC: `Authentication-Results` は偽装可能なため、受信サーバーのauthserv-id等を信頼設定で検証できた場合のみ補助情報として利用する。現段階のパーサーは値を保持するだけで判定へ反映しない。
- `Return-Path` も受信経路で付与されたことを確認できた場合のみFromとの不一致判定に利用する。
- URL: IPリテラル、Punycode、短縮URL、表示文字列と実リンク先の差異、ローカル悪性ドメインリストを評価
- 外部URL照会: 初期OFF。API送信時の情報開示を明示
- 添付: ファイルを実行・展開しない。MIME、拡張子、マジックバイトを確認。ZIPは上限付きで中央ディレクトリを検査し、ZIP bomb対策を行う
- 発信国: オプション。信頼できる接続元IPを選択し、ローカルGeoIPデータで補助判定。国だけで迷惑判定しない

## 4. メール操作

- 手動判定
- 選択メールの一括判定
- 正常/迷惑としての手動学習
- 受信済みメールの再判定
- 判定理由・スコアの表示
- 件名プレフィックス、カラーラベル、独自ヘッダーは実機SDKで安全性を確認してから実装
- 自動振り分けは監査モードの検証後、利用者が明示的にONにした場合のみ
- 削除操作は提供しない

## 5. AI API補助判定

- 初期設定OFF
- ローカル判定の保留・ユーザー報告メールなど、対象を限定して非同期キューへ登録
- Becky!の受信コールバックでAPI応答を待たない
- APIには必要最小限の情報だけ送信する。本文・ヘッダー送信の前に利用者へ明示する
- APIキーはDLLや設定ファイルへ平文で埋め込まず、Windows DPAPI等で保護
- AI出力は迷惑/正常/判定不能、確信度、理由を構造化して受け取る
- AI判定は仮ラベルとして保存し、ユーザー確認前に確定教師データにしない
- タイムアウト、レート制限、通信失敗時はローカル判定を維持
- 同一メールの重複照会を防ぐ。本文そのものではなく安全なハッシュを照会識別子に利用
- メール本文中の命令文は信頼しない。メールは分析対象データとして扱う

## 6. 学習DB・肥大化対策

### 6.1 保存方針
- SQLiteを第一候補とする。Win32/x86でビルド・配布可能な構成を検証する。
- メール本文・完全ヘッダーは原則保存しない。
- 単語ごとの正常/迷惑文書頻度、学習サンプル数、ユーザーリスト、最小限の訂正履歴を保存する。
- 重複学習防止用ハッシュは必要最小限で保持し、保存期間を設定可能にする。
- AI照会履歴は本文を含めず、設定可能な保存期間で整理する。

### 6.2 スリム化
- 語彙数上限、最小出現頻度、最終使用時刻を管理する。
- 低頻度・長期間未使用の語彙を優先して整理する。
- 単純削除だけでなく、古い頻度情報の減衰を検討する。
- 学習統計を集約し、個々のメール本文を残さない。
- SQLiteの不要レコード削除とVACUUMを別工程として扱う。
- 自動整理前にバックアップまたは復元ポイントを確保する。
- 容量警告・目標容量・上限値は設定可能とする。上限到達時に無断で大量削除せず、警告と安全な整理候補を提示する。
- スリム化前後のDB容量、語彙数、学習件数を表示する。

### 6.3 初期目標値（実測後に調整）
- DB目標容量: 50 MiB
- 警告: 100 MiB
- 上限目安: 200 MiB
- AI照会履歴: 30日
- 数値は暫定値。ユーザーのメール量・精度試験により調整する。

## 7. 運用・品質要件

- メールサイズ、MIMEパート数、ZIPエントリー数、解析時間に上限を設ける。
- 不正メール・巨大メール・不正MIMEでBecky!を停止させない。
- DLL境界を越えて例外を伝播させない。
- ログに本文・認証情報・APIキーを記録しない。
- 学習DBのバックアップ・復元・スキーマバージョン管理を用意する。
- CIはWindows x86でビルド・単体テストを行う。Becky!実機試験は別途必要。

## 8. 参考にする公開ソフトウェア

- Annoyance Filter: ベイジアン確率計算、判定保留、学習の考え方
- 秀丸スパムフィルター for Becky!: 迷惑ワード、信頼ワード、URL/添付/発信国の補助判定
- 深海魚フィルター: 日本語解析、安心/迷惑リスト、再判定、学習データ管理、統計・操作性

## 診断ログ

運用ログと詳細テストログは設定ファイルで個別に制御する。通常ログは初期状態で有効、詳細テストログは初期状態で無効。詳細ログは解析経路・MIME構成・判定根拠・警告・エラーを調査するためのもので、メール本文や個別ヘッダー値は記録しない。ログ全体の停止設定を優先する。
